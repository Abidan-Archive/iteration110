# Iteration110 Server Config
The Abidan Archive runs on a NixOS server. This repository configures the host,
Laravel services, and the new MediaWiki at **https://next.abidanarchive.com**.
The existing **https://wiki.abidanarchive.com** continues proxying the legacy wiki.

## Layout

- `configuration.nix`: imports the host modules and retains `system.stateVersion = "23.11"`.
- `settings.nix`: application/domain names, paths, deployment user, and Laravel PHP package.
- `modules/system.nix`: boot, networking, SSH, host tools, and Nix maintenance.
- `modules/users.nix`: deployment and application users/groups.
- `modules/secrets.nix`: SOPS declarations, ownership, and secret templates.
- `modules/nginx.nix`: Archive virtual hosts, legacy wiki proxy, TLS, and status endpoint.
- `modules/archive.nix`: Laravel PHP-FPM, queue worker, storage directories, and OIDC environment paths.
- `modules/databases.nix`: MariaDB, Meilisearch, and Redis.
- `modules/monitoring.nix`: Linode Longview.
- `modules/mediawiki.nix`: new wiki, extensions, OIDC login, and username-sync logging.
- `mediawiki/AbidanUsernameSync`: login-time username synchronization extension and disposable SQLite integration tests.
- `docs/mediawiki-spoilers.md`: editor guide to spoiler blocks and collapsible sections.

The flake now targets **NixOS 26.05**; application PHP stays on **8.3**. The lockfile
also pins updated unstable and SOPS inputs. The installation's state version is
deliberately retained, so upgrading packages does not reset compatibility defaults.

## SOPS-managed OpenID Connect keys

Secret contents are not generated by Nix or committed as plaintext. Add the new
`ABIDAN_OIDC_PRIVATE_KEY` field manually through `sops secrets.yaml`, as a multiline
RSA private PEM. The other two wiki fields were already declared in the previous
configuration; ensure their encrypted entries are present too:

| SOPS field | Purpose | Runtime reader |
| --- | --- | --- |
| `ABIDAN_OIDC_PRIVATE_KEY` | RS256 ID-token signing key | `abidan`, mode `0400` |
| `MEDIAWIKI_OAUTH_CLIENT_SECRET` | Shared OIDC client secret | `mediawiki`, mode `0400`; SOPS renders a separate `0400` copy for `abidan` |
| `MEDIAWIKI_INIT_ADMIN_PW` | Initial wiki bootstrap admin password | `mediawiki`, mode `0400` |

Generate a new PEM from the Laravel development shell with:

```sh
php artisan oauth:keys --show
```

This prints only a newly generated PEM and does not write/replace a key file.
Use a private local terminal, not CI or a recorded/shared console. Save the output
in the encrypted SOPS field. If retaining an existing production signing key,
import that existing PEM instead of generating a replacement.

SOPS installs the private key at `/run/secrets/ABIDAN_OIDC_PRIVATE_KEY` and the
Laravel client-secret copy at `/run/secrets/rendered/ABIDAN_OAUTH_CLIENT_SECRET`.
The wiki reads the shared source secret from `/run/secrets/MEDIAWIKI_OAUTH_CLIENT_SECRET`.
No PEM is copied into `/srv`, a deployment artifact, or the Nix store as plaintext.
Relevant services restart when these SOPS-managed files change.

The host appends its canonical URLs and OIDC runtime-file paths to the SOPS-rendered
`abidan.env`. Each release links `.env` to `/etc/abidan/runtime.env`, and PHP-FPM and
the queue also receive these host-owned values from NixOS:

```dotenv
APP_URL=https://abidanarchive.com
MEDIAWIKI_URL=https://next.abidanarchive.com
MEDIAWIKI_REDIRECT_URI=https://next.abidanarchive.com/wiki/Special:PluggableAuthLogin
OAUTH_PRIVATE_KEY_PATH=/run/secrets/ABIDAN_OIDC_PRIVATE_KEY
OAUTH_CLIENT_MEDIAWIKI_SECRET_FILE=/run/secrets/rendered/ABIDAN_OAUTH_CLIENT_SECRET
```

The application reads the client-secret file at request time, so the secret is
not embedded in Laravel's cached configuration. A configured but missing file
does not fall back to a stale plaintext `.env` value. Local development can still
use `OAUTH_CLIENT_MEDIAWIKI_SECRET` and `php artisan oauth:keys` with local storage.

## Managed production environment

The host now includes `abidan-config-refresh.service`: it atomically rebuilds Laravel's
configuration cache as the application user, then reloads PHP-FPM and restarts the
queue. A SOPS-rendered complete `.env` can trigger it automatically after a NixOS
rebuild. Managed dotenv is enabled and sourced from the pinned application repository.

See **[the production environment migration guide](docs/production-environment.md)**
for preserving `APP_KEY`, storing the encrypted environment in the application
repository, pinning it in NixOS, and enabling `services.abidan.environment`.
The deployment workflow uses a narrow passwordless service trigger; no sudo password
is passed through GitHub Actions.

## Deploy

For the Laravel 13 and restricted deployment account rollout, follow
**[deployment hardening](docs/deployment-hardening.md)** first, including the GitHub
settings and one-time ownership migration.

1. Add the PEM to SOPS and ensure the host's age identity is still available at
   `/home/telariel/.config/sops/age/keys.txt`. The normal build intentionally checks
   that the declared encrypted fields exist.
2. Prepare the database/search upgrade described below, then build:

   ```sh
   nix build .#nixosConfigurations.abidan.config.system.build.toplevel --no-link
   ```

3. Apply the host configuration, substituting the correct SSH connection:

   ```sh
   nixos-rebuild -j auto switch --flake .#abidan \
     --target-host USER@HOSTNAME --verbose --use-remote-sudo
   ```

4. Deploy the updated Laravel application through its `prod` workflow. The NixOS
    host must be deployed first because the workflow now requires `/etc/abidan/runtime.env`.
    For the first rollout, publish the encrypted dotenv file to `prod` without the
    new workflow first; update the host input and deploy NixOS, then publish the
    SOPS-only workflow. See the migration guide for this ordering.
   This deploy must include the provider, signing service, file-based secret support,
   CSRF exemption, and Inertia/Discord return-to-wiki fixes.
5. Test discovery at `https://abidanarchive.com/.well-known/openid-configuration`,
   public keys at `https://abidanarchive.com/oauth/jwks`, and login at
   `https://next.abidanarchive.com/wiki/Special:UserLogin`. Then change an Archive
   username and reauthenticate to check the wiki rename.

Use the Git-filtered `.#abidan` form and track new module/extension files before
building. Do not use `path:.` here: it includes ignored backups, development state,
and Git history in the source copied into the Nix store. The `devenv` deploy helper
now uses the correct `abidan` output name. The remote SSH user needs wheel permissions.

## Deployment gaps and follow-ups

- **The declared SOPS fields must exist before deployment.** `secrets.yaml` has not
  been decrypted or edited by this work. Validation against the local encrypted
  dotenv currently reports missing `MEDIAWIKI_INIT_ADMIN_PW`; ensure that entry and
  `MEDIAWIKI_OAUTH_CLIENT_SECRET` are present before building normally.
- **The application environment must be published before advancing the pin.** The
  current remote `prod` revision predates `secrets/production.env`. Publish that
  encrypted file first, run `nix flake update abidan-environment`, then deploy the
  host before publishing the SOPS-only application workflow.
- **Stateful upgrades need production preparation.** The new lock resolves
  MariaDB **11.4.12**, Meilisearch **1.43.1**, and Redis **8.8.3**. The running host's
  database/index data was not inspected. Prepare backups and an appropriate MariaDB
  upgrade and Meilisearch dump/import or rebuild plan before switching; a NixOS
  generation rollback does not roll back database/index formats. Verify the
  application's Meilisearch client against the upgraded service.
- **DNS/TLS must work for `next.abidanarchive.com`.** Its virtual host enables ACME
  HTTP-01 validation; DNS must point to this server and port 80 must be reachable.
  The host continues to disable IPv6, so avoid pointing an unusable AAAA record at it.
- **Legacy wiki data is not migrated by this configuration.** Plan the database,
  uploads, imported-user/OIDC linking, and final hostname cutover separately. The
  new wiki uses the existing local `mediawiki` database and `/var/lib/mediawiki` state.
  Existing local wiki users are not automatically linked by email or username.
- **Wiki administration needs an Archive-backed account.** Local wiki login is
  disabled, including the bootstrap admin's password login. Archive's verified
  `wiki_roles` claim maps `wiki_admin` to `sysop` and `wiki_moderator` to `moderator`.
  Assignments and removals take effect on the next wiki login; the Archive ACL owns
  privileged membership. See `mediawiki/AbidanUsernameSync/README.md` for details.
- **SSO sessions remain separate.** Archive logout does not invalidate an existing
  wiki session; username changes synchronize at the next wiki login. Rename sources
  are maintained in this repository under `mediawiki/AbidanUsernameSync`.
- **Existing release permissions may need one-time preparation.** New deployments
  use the deployer's ownership and the application group, and cleanup runs without
  sudo. Older root/application-owned releases may need administrator cleanup until
  the old generations have aged out. The current release's permissions must permit
  the application user to update its `.env` link and `bootstrap/cache`.
- **The original DB password setup script assumes SQL-safe secret values.** It
  interpolates passwords into SQL literals and retains its old ordering reference
  to `sops-nix.service`. Its secrets were not inspected or changed during this refactor.
